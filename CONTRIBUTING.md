# Contributing

Thanks for looking. A few things about this project are unusual, and knowing them will
save you time.

## Read this first

**[docs/DEVELOPMENT.md](docs/DEVELOPMENT.md) is not a victory lap.** It records twelve
optimisations that were attempted and describes, for each, whether it helped and why.
Several did nothing at all. If you are about to try an optimisation, read that first —
there is a reasonable chance it is already in there with a measurement attached.

## The rule this project runs on

> **Only reductions in work have ever helped. Every change to the shape of the code has
> been a no-op.**

| Changed the *shape* | Result |
|---|---|
| Smaller enum (56 → 40 bytes) | +1.7% |
| O(1) cache index instead of a scan | 0% |
| Flags as plain statics instead of thread-locals | 0%, and it broke threading |
| Flattened 338-instruction evaluator | 0% |
| `lto = "fat"` | 0% |
| `target-cpu = "native"` | 0% |

| Reduced the *work* | Result |
|---|---|
| `flat_cache` snapped and memoised | 1.35× |
| Noise samples memoised | 1.37× |
| Lerp inside the borrow instead of copying 64 bytes out | 1.20× |

If you have a performance idea, say which side of that line it falls on, and measure it
with `rust/mcgen-core/examples/microbench.rs` before and after.

## Correctness rules

1. **Bit-exact or it is a bug.** Comparisons are raw `f64` bit patterns, not tolerances.
   Nothing in the density layer is "close enough".
2. **Never break parity silently.** `./scripts/check-parity.sh` must pass. It has twelve
   checks and the twelfth — `column` — compares against vanilla's own `NoiseChunk`. It
   caught three bugs that the other eleven all missed; treat a failure there as real.
3. **Check 12 needs a chunk-scoped cache boundary.** `compute_chunked` and
   `clear_interpolation_cache` exist because the caches are per-chunk. If you add a cache,
   say when it is invalidated and make sure the parity suite covers the boundary.
4. **Prefer failing loudly.** An unknown density type is a hard error, never an
   approximation. A silently wrong world is worse than a crash.

## Adding a density function type

1. Add the variant to `DensityFunction` in `rust/mcgen-core/src/density.rs`.
2. Parse it in the builder.
3. Implement both `compute` and `compute_chunked` behaviour. If it is a `Marker`, the raw
   reading is a passthrough and the chunked reading does the real work — see how
   `Interpolated` does it.
4. Add it to `TALLY_NAMES` if it is worth counting.
5. Add a case to the oracle and a check to `check-parity.sh`.

## Adding a command

Commands live in `java/neoforge-mod/src/mcgen/McGenCommands.java`. Two rules there:

- **Nothing throws out into the server.** Every failure path sends a message and returns.
- **Nothing mutates a world.** The command tree is read-only.

If the command needs native data, add an entry point to `rust/mcgen-ffi/src/lib.rs`, a
declaration in `McGenNative.java`, and a function in `jni_shim.c`. Bump
`MCGEN_ABI_VERSION` and `McGenMod.ABI_VERSION` together — they are checked against each
other at load, and a mismatch disables the engine rather than misbehaving.

## Style

Rust: `cargo fmt` and `cargo clippy` clean. The build must produce **zero warnings** — it
currently does, and that is worth keeping.

Java: compiled with `-Xlint:all`. Same rule.

Comments should say *why*, not *what*. The existing code has a lot of "this looks odd
because vanilla does X" comments; that is the kind of thing worth writing down.

## Reporting a bug

Please include:

- the output of `/mcgen status`,
- the full output of `/mcgen chunk <x> <z>` for a chunk you know was generated by
  vanilla terrain,
- your NeoForge and Minecraft versions.

If `/mcgen chunk` reports disagreements that are **not** trees or carved cave air, that is
the interesting kind and I would like to hear about it.
